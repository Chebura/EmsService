# EMS Service — руководство пользователя

EMS Service рассылает одно и то же текстовое письмо по спискам получателей (группам) через ваш почтовый
сервер (SMTP). Сервис работает в фоне, а настраивается и запускается через браузер.

## 1. Установка и запуск

### Установщик для Windows (рекомендуется)

Запустите `EmsService.msi` и следуйте мастеру. Установщик:

- ставит сервис в `C:\Program Files\EMS Service` (папку можно изменить);
- регистрирует и запускает службу Windows **EMS Service**, которая стартует вместе с компьютером и
  перезапускается при сбое;
- добавляет ярлыки **EMS Service** на рабочий стол и в меню «Пуск»; они открывают веб-интерфейс по адресу по
  умолчанию **http://localhost:5080/**.

После установки откройте ярлык или **http://localhost:5080**.

Обновление — запустите установщик новой версии поверх старой. Настройки, тексты писем, задачи, журналы и
`appsettings.json` сохраняются. Удаление — «Параметры → Приложения» или «Программы и компоненты»; эти файлы
остаются в папке установки, удалите её вручную, если они не нужны.

Если вы изменили порт в `appsettings.json`, ярлыки по-прежнему ведут на порт 5080 — открывайте
интерфейс по новому адресу вручную.

### Запуск без установки

Сервис поставляется одним исполняемым файлом с папками рядом. Устанавливать .NET не нужно.

Скопируйте папку с сервисом в постоянное место, например `C:\ems` (Windows) или `/opt/ems` (Linux),
и запустите:

| Система | Команда |
|---|---|
| Windows | `ems-service.exe` |
| Linux | `./ems-service` |

Откройте в браузере **http://localhost:5080**.

Остановить сервис, запущенный в окне консоли, — `Ctrl+C`.

Кнопка ☾ / ☀ в правом верхнем углу интерфейса переключает тёмную и светлую тему. По умолчанию тема берётся из
настроек системы, выбранная тема запоминается в браузере.

### Запуск как службы вручную

Если вы не используете установщик, службу можно зарегистрировать вручную.

**Windows** (командная строка от имени администратора):

```
sc create EmsService binPath= "C:\ems\ems-service.exe" start= auto
sc start EmsService
```

Удаление службы: `sc stop EmsService`, затем `sc delete EmsService`.

**Linux (systemd)** — создайте файл `/etc/systemd/system/ems.service`:

```
[Unit]
Description=Email Mass Sender service

[Service]
Type=notify
ExecStart=/opt/ems/ems-service
WorkingDirectory=/opt/ems
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

и выполните `sudo systemctl enable --now ems`.

### Доступ с другого компьютера

По умолчанию интерфейс открывается только на том компьютере, где запущен сервис. Чтобы открыть его по сети,
в файле `appsettings.json` замените адрес и перезапустите сервис:

```json
"Urls": "http://0.0.0.0:5080"
```

> **Важно.** В интерфейсе нет логина и пароля: любой, кто может открыть страницу, может менять настройки и
> запускать рассылку. Открывайте доступ только во внутренней сети и ограничьте его файрволом.

Там же можно сменить порт, например `"http://localhost:8080"`.

## 2. Первая рассылка за 5 шагов

1. **Настройки → Отправитель.** Укажите адрес отправителя (тот, от имени которого уходят письма) и имя,
   которое увидят получатели.
2. **Настройки → SMTP-сервер.** Укажите сервер, порт, логин и пароль почтового ящика, включите SSL/TLS, если
   сервер этого требует. Нажмите **«Сохранить»**.
   Пример для Яндекса: сервер `smtp.yandex.ru`, порт `587`, SSL включён, пароль — пароль приложения.
3. **Группы → «Добавить».** Задайте имя группы, тему письма и список получателей (по одному адресу в строке).
   Нажмите **«Сохранить группы»**.
4. **Группы → «Текст письма».** Введите текст и нажмите **«Сохранить текст»**.
   Поле текста становится доступным после сохранения группы.
5. **Рассылка → «Запустить рассылку».** Ход рассылки виден в таблице задач и на вкладке «Журнал».

> Совет: для пробы создайте группу с одним своим адресом, а в настройках SMTP снимите флажок
> «Отправлять письма» — рассылка пройдёт без реальной отправки. Затем включите флажок обратно.

## 3. Вкладка «Рассылка»

### Состояние и кнопки

| Элемент | Описание |
|---|---|
| Состояние | «ожидание» или «выполняется рассылка», время последнего запуска и результат |
| **Запустить рассылку** | Начинает рассылку. Недоступна, пока рассылка уже идёт |
| **Остановить** | Прерывает рассылку. Уже отправленные письма запоминаются и повторно не уйдут |

Под кнопками указано, какие группы будут разосланы.

Результат последнего запуска:

| Результат | Значение |
|---|---|
| завершена | Все письма обработаны: отправлены либо исчерпаны попытки / истёк срок актуальности |
| остановлена | Рассылку остановили кнопкой или сервис был остановлен |
| ошибка | Рассылка прервалась из-за ошибки; текст ошибки показан под состоянием |

### Проверка перед запуском

Перед стартом сервис проверяет, что рассылку можно выполнить. Если что-то не так, рассылка не начинается, а
на экране появляется причина:

| Сообщение | Что сделать |
|---|---|
| Не задан SMTP-сервер | Заполните сервер на вкладке «Настройки» |
| Не задан адрес отправителя | Заполните адрес отправителя |
| Нет ни одной группы получателей | Добавьте группу |
| Группа `…`: нет файла с текстом письма | Сохраните текст письма группы |
| Группа `…`: текст письма пуст | Введите и сохраните текст письма |
| Группа `…`: нет получателей | Добавьте получателей |
| Группа `…` из списка групп для рассылки не найдена | Исправьте поле «Группы для рассылки» |

### Таблица задач

Задача — это рассылка одного текста одной группе. Она создаётся при первом запуске и хранит, кому письмо уже
ушло.

| Колонка | Значение |
|---|---|
| Всего | Получателей в задаче |
| Отправлено | Письма отправлены |
| Ожидают | Ещё будут отправлены (в том числе повторно после ошибки) |
| Ошибка | Последняя попытка отправки завершилась ошибкой |
| Не отправлено | Попытки исчерпаны или истёк срок актуальности — письмо больше не будет отправляться |

Щёлкните по имени задачи, чтобы увидеть каждого получателя: состояние, время последней попытки, сколько
попыток осталось и текст ошибки.

Кнопка **«Удалить»** удаляет задачу (подтвердите повторным нажатием). Следующий запуск создаст её заново и
отправит письмо **всем** получателям группы ещё раз. Удалять задачи во время рассылки нельзя.

## 4. Вкладка «Настройки»

После изменений нажмите **«Сохранить»** внизу страницы. Новые настройки действуют со следующего запуска
рассылки; перезапускать сервис не нужно.

Интервалы времени вводятся в формате `[дни.]часы:минуты:секунды`, например `00:00:01` — 1 секунда,
`00:01:00` — 1 минута, `7.00:00:00` — 7 дней.

### Отправитель

| Поле | Описание |
|---|---|
| Адрес отправителя | Адрес в поле «От кого». Обычно совпадает с почтовым ящиком SMTP |
| Имя отправителя | Имя в поле «От кого», например название компании |
| Кодировка писем | Кодировка текста и темы. Пусто — UTF-8. Для старых почтовых программ можно указать `windows-1251` |

### SMTP-сервер

| Поле | Описание |
|---|---|
| Отправлять письма | Если флажок снят, отправка только имитируется: письма считаются отправленными, но не уходят |
| Сервер, Порт | Адрес и порт SMTP-сервера (обычно 587 или 465) |
| Пользователь, Пароль | Учётные данные почтового ящика |
| Использовать SSL/TLS | Шифрование соединения; большинство серверов его требуют |

Пароль после сохранения не показывается. Оставьте поле пустым, чтобы не менять сохранённый пароль.

### Отправка

| Поле | Описание |
|---|---|
| Группы для рассылки | Имена групп через `;`, например `clients;partners`. Пусто — все группы |
| Потоков | Сколько писем отправляется одновременно. Для большинства почтовых сервисов оставьте `1` |
| Задержка между письмами в потоке | Пауза между письмами. Помогает не попасть под ограничения почтового сервера |

### Повторная отправка

| Поле | Описание |
|---|---|
| Повторять отправку при ошибке | Если выключено, каждому получателю делается одна попытка |
| Задержка между попытками | Через сколько повторить отправку после ошибки |
| Максимум попыток | Сколько всего попыток делается для одного получателя |

### Задачи

| Поле | Описание |
|---|---|
| Каталог задач | Где хранятся файлы задач (по умолчанию `./tasks` рядом с сервисом) |
| Срок хранения задач | Через сколько удаляются старые задачи, если включено удаление |
| Удалять устаревшие задачи | Удалять задачи старше срока хранения при запуске рассылки |
| Пересоздавать задачи при каждом запуске | **Осторожно:** при каждом запуске письмо уйдёт всем получателям заново |

## 5. Вкладка «Группы»

Слева — список групп и число получателей в каждой. Выберите группу, чтобы изменить её.

| Поле | Описание |
|---|---|
| Имя группы | Используется в имени файла задачи. Нельзя использовать `;` и символы, недопустимые в именах файлов (`\ / : * ? " < > \|`) |
| Тема письма | Тема, которую увидят получатели |
| Файл с текстом письма | Где хранится текст. Для новой группы подставляется `texts/<имя>.txt` |
| Кодировка | Кодировка письма этой группы. Пусто — как в настройках |
| Актуальность | Сколько времени после создания задачи продолжать попытки отправки. По истечении срока неотправленные письма больше не отправляются |
| Получатели | По одному адресу в строке (можно также через пробел, запятую или `;`). Повторы удаляются автоматически |

Кнопки:

- **Добавить** — новая группа.
- **Сохранить группы** — сохраняет все группы. Группы можно настраивать, даже если SMTP ещё не заполнен.
- **Удалить группу** — удаляет группу (подтвердите повторным нажатием, затем нажмите «Сохранить группы»).

### Текст письма

Письмо отправляется как обычный текст (без оформления и вложений). Введите текст и нажмите
**«Сохранить текст»**. Над полем показано, в каком файле и в какой кодировке хранится текст.

Если вы переименовали группу или сменили файл текста, сначала нажмите «Сохранить группы», затем сохраните
текст.

> Изменение текста письма — это новая рассылка: при следующем запуске письмо с новым текстом получат все
> получатели группы, даже те, кому уже ушёл старый текст.

## 6. Вкладка «Журнал»

Показывает последние 500 записей журнала и обновляется автоматически (флажок «Автообновление»).

Полезные записи:

| Запись | Значение |
|---|---|
| `Sending run started` / `Sending run finished: Completed` | Начало и окончание рассылки |
| `Mail to '…' sent` | Письмо отправлено |
| `Email sending error (item receiver: '…')` | Ошибка отправки получателю; ниже — причина |
| `Task done with SUCCESS. … sent: 2, failed: 0` | Итог прохода по задаче. SUCCESS означает, что по задаче больше нечего отправлять (письма отправлены или попытки исчерпаны), а не то, что все письма доставлены, — смотрите `sent` и `failed` |
| `Items are waiting for retry. Next pass in …` | Часть писем ждёт повторной попытки |
| `Sending run rejected: …` | Запуск отклонён проверкой (см. раздел 3) |
| `Settings are not saved: …` | Настройки не сохранены из-за ошибок |

Полный журнал хранится в файлах `logs/ems-<дата>.log` (последние 30 файлов).

## 7. Как работает рассылка

1. При запуске для каждой выбранной группы создаётся (или берётся существующая) задача. Задача определяется
   группой и текстом письма: пока текст не меняется, используется та же задача.
2. Письмо отправляется всем, кому оно ещё не ушло.
3. Если отправка получателю не удалась, следующая попытка будет через «Задержку между попытками».
   Рассылка ждёт и повторяет попытки.
4. Рассылка заканчивается, когда по каждому получателю письмо отправлено, исчерпаны попытки или истёк срок
   актуальности группы. Её также можно остановить кнопкой.

Следствия:

- **Повторный запуск того же текста не отправит письма второй раз** тем, кому они уже ушли. Чтобы разослать
  тот же текст заново, удалите задачу на вкладке «Рассылка».
- **Остановка безопасна**: при следующем запуске рассылка продолжится с того же места.
- Если в рассылке есть недоступные адреса и включены повторы, рассылка может длиться долго (до «Максимума
  попыток» × «Задержка между попытками» или до конца срока актуальности). Следите за ней на вкладке
  «Рассылка» или остановите кнопкой.

## 8. Файлы сервиса

Все пути — относительно папки сервиса.

| Файл / папка | Назначение |
|---|---|
| `emssettings.json` | Настройки рассылки (то, что вы задаёте в интерфейсе). Создаётся при первом запуске |
| `appsettings.json` | Адрес интерфейса (`Urls`) и путь к файлу настроек |
| `nlog.config` | Настройка журнала |
| `texts/` | Тексты писем групп |
| `tasks/` | Задачи рассылки (состояние отправки по каждому получателю) |
| `logs/` | Файлы журнала |

Для резервной копии достаточно сохранить `emssettings.json`, `texts/` и `tasks/`.

> В `emssettings.json` пароль SMTP хранится открытым текстом. Ограничьте доступ к папке сервиса.

## 9. Вопросы и проблемы

**Страница не открывается.**
Проверьте, что сервис запущен (в консоли есть строка `Now listening on: http://localhost:5080`) и вы
открываете тот же адрес и порт. С другого компьютера — см. «Доступ с другого компьютера».

**Кнопка «Запустить рассылку» показывает ошибку.**
Это проверка перед запуском, причина указана в сообщении — см. таблицу в разделе 3.

**Письма не уходят, в журнале `Email sending error`.**
Проверьте сервер, порт, логин, пароль и SSL. Многие почтовые сервисы (Яндекс, Mail.ru, Gmail) требуют
отдельный «пароль приложения» вместо обычного пароля ящика. Проверьте также, что адрес отправителя совпадает
с ящиком, от имени которого вы входите.

**Рассылка завершилась мгновенно, писем нет.**
Все письма этой задачи уже были отправлены раньше. Чтобы разослать снова, удалите задачу на вкладке
«Рассылка» или измените текст письма.

**Рассылка идёт очень долго.**
Скорее всего, часть адресов не принимает письма и сервис повторяет попытки. Посмотрите столбец «Ошибка» и
детали задачи. Уменьшите «Максимум попыток» или остановите рассылку.

**Почтовый сервер блокирует отправку как спам.**
Увеличьте «Задержку между письмами в потоке» и оставьте 1 поток.

**Получатели видят «кракозябры».**
Укажите кодировку `utf-8` (или `windows-1251` для старых почтовых программ) в настройках или в группе и
сохраните текст письма заново.

**Настройки не сохраняются.**
В правом нижнем углу появится список ошибок (например, некорректный адрес получателя). Исправьте указанные значения и сохраните снова.
