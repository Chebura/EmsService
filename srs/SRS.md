# Спецификация требований к программному обеспечению (SRS)

**Продукт:** EMS Service — сервис массовой рассылки электронной почты
**Версия документа:** 1.0
**Дата:** 2026-10-13
**Структура:** по ISO/IEC/IEEE 29148:2018 (раздел 9.6, SRS)

---

## 1. Введение

### 1.1 Назначение

Документ определяет требования к EMS Service — серверному приложению, выполняющему массовую рассылку
текстовых писем по группам получателей через SMTP. Документ предназначен для разработчиков,
тестировщиков и администраторов, сопровождающих сервис.

### 1.2 Область применения

EMS Service является серверной версией консольной утилиты Email Mass Sender (EMS). Логика рассылки
(задачи, повторная отправка, многопоточность) перенесена из EMS; запуск и настройка выполняются через
веб-интерфейс вместо командной строки и ручного редактирования файлов.

Вне области применения: HTML-письма и вложения, расписание запусков, аутентификация и разграничение
доступа, HTTPS, отслеживание доставки и прочтения.

### 1.3 Термины и сокращения

| Термин | Определение |
|---|---|
| Группа | Именованный набор: список получателей, тема, файл с текстом письма, кодировка, срок актуальности. |
| Задача | Файл `<группа>_<MD5 текста>.task`, хранящий состояние отправки текста письма получателям группы. |
| Элемент задачи | Запись о получателе в задаче: число оставшихся попыток, время следующей попытки, ошибка. |
| Прогон | Один запуск рассылки от нажатия «Запустить» до завершения или остановки. |
| Актуальность | Срок, по истечении которого элемент задачи больше не обрабатывается. |
| Повторная отправка (roll-up) | Стратегия повторных попыток отправки при ошибке. |
| UI | Веб-интерфейс сервиса. |

## 2. Общее описание

### 2.1 Перспектива продукта

Автономное приложение ASP.NET Core (.NET 10), объединяющее в одном процессе:

- HTTP-сервер (Kestrel) с веб-интерфейсом и REST API;
- фоновый сервис (`BackgroundService`), выполняющий рассылку;
- хранилище настроек в JSON-файле;
- логирование через NLog.

```
 Браузер ──HTTP──► Kestrel ─► REST API ─┬─► Хранилище настроек ──► emssettings.json
                                        ├─► Фоновый сервис ──► Сервис рассылки ──SMTP──► Почтовый сервер
                                        │                              └──► tasks/*.task, texts/*.txt
                                        └─► Буфер журнала NLog ◄── NLog ──► logs/*.log, консоль
```

### 2.2 Функции продукта

1. Настройка параметров рассылки через UI.
2. Управление группами получателей и текстами писем через UI.
3. Запуск рассылки кнопкой и её остановка.
4. Выполнение рассылки до отправки всех писем или исчерпания попыток.
5. Просмотр состояния прогона, задач и получателей.
6. Просмотр журнала.

### 2.3 Классы пользователей

| Класс | Описание |
|---|---|
| Оператор | Настраивает группы и тексты, запускает и останавливает рассылку через UI. |
| Администратор | Устанавливает сервис, настраивает `appsettings.json` и `nlog.config`, ограничивает сетевой доступ. |

### 2.4 Операционная среда

- ОС: Windows, Linux, macOS (x64, arm64) — любая платформа, поддерживаемая .NET 10; на Linux требуется ICU.
- Запуск консольно, как служба Windows или как служба systemd.
- Self-contained: установленный .NET Runtime не требуется.
- Браузер: современный браузер с поддержкой ES2020.

### 2.5 Ограничения

- C-1. Платформа: .NET 10, ASP.NET Core.
- C-2. Логгер: NLog.
- C-3. Только HTTP; HTTPS не используется.
- C-4. Аутентификация не используется.
- C-5. Развёртывание self-contained.
- C-6. Настройки хранятся в файле конфигурации, база данных не используется.

### 2.6 Допущения и зависимости

- A-1. Доступ к UI ограничивается средствами сети (по умолчанию сервис слушает только `localhost`).
- A-2. SMTP-сервер доступен и принимает аутентификацию логином и паролем.
- A-3. Одновременно работает один экземпляр сервиса с данным каталогом задач.

## 3. Конкретные требования

Приоритеты: **В** — высокий (обязательно), **С** — средний, **Н** — низкий.

### 3.1 Внешние интерфейсы

#### 3.1.1 Пользовательский интерфейс

| ID | Требование | Приоритет |
|---|---|---|
| UI-1 | UI доступен по корневому адресу сервиса и представляет собой одностраничное приложение на русском языке. | В |
| UI-2 | UI содержит вкладки «Рассылка», «Настройки», «Группы», «Журнал». | В |
| UI-3 | Вкладка «Рассылка» содержит отдельную кнопку «Запустить рассылку» и кнопку «Остановить». | В |
| UI-4 | Кнопка «Запустить рассылку» недоступна во время прогона; «Остановить» — вне прогона. | В |
| UI-5 | Состояние прогона обновляется автоматически не реже одного раза в 3 секунды. | С |
| UI-6 | UI корректно отображается при ширине экрана от 360 px и поддерживает тёмную тему системы. | Н |
| UI-7 | Ошибки валидации и операций показываются пользователю текстом. | В |
| UI-8 | Удаление (задачи, группы) требует подтверждения повторным нажатием. | С |

#### 3.1.2 Программный интерфейс (REST API)

Все ответы — JSON в camelCase. Ошибки — `{"errors": ["..."]}`.

| ID | Метод и путь | Назначение | Ответы |
|---|---|---|---|
| API-1 | `GET /api/status` | Версия, состояние прогона, путь к файлу настроек | 200 |
| API-2 | `POST /api/run` | Запустить прогон | 202; 400 — настройки не готовы; 409 — прогон уже идёт |
| API-3 | `POST /api/stop` | Остановить прогон | 202; 409 — прогон не идёт |
| API-4 | `GET /api/settings` | Настройки (без пароля SMTP) и признак заданного пароля | 200 |
| API-5 | `PUT /api/settings` | Сохранить настройки | 204; 400 — ошибки валидации |
| API-6 | `GET /api/groups/{name}/text` | Текст письма группы | 200; 404 |
| API-7 | `PUT /api/groups/{name}/text` | Сохранить текст письма группы | 204; 404 |
| API-8 | `GET /api/tasks` | Список задач со сводкой | 200 |
| API-9 | `GET /api/tasks/{name}` | Элементы задачи | 200; 404 |
| API-10 | `DELETE /api/tasks/{name}` | Удалить задачу | 204; 404; 409 — во время прогона |
| API-11 | `GET /api/logs?count=N` | Последние N записей журнала (по умолчанию 300) | 200 |

| ID | Требование | Приоритет |
|---|---|---|
| COM-1 | UI и API доступны по HTTP на адресе из параметра `Urls` (по умолчанию `http://localhost:5080`). | В |
| COM-2 | Отправка писем — по SMTP с настраиваемыми сервером, портом, SSL/TLS и учётными данными. | В |

### 3.2 Функциональные требования

#### 3.2.1 Настройки

| ID | Требование | Приоритет |
|---|---|---|
| F-SET-1 | Сервис хранит настройки рассылки в JSON-файле (`EmsSettingsFilePath`, по умолчанию `emssettings.json`). | В |
| F-SET-2 | Если файл отсутствует, сервис создаёт его с настройками по умолчанию. | В |
| F-SET-3 | Если файл повреждён, сервис запускается с настройками по умолчанию и пишет ошибку в журнал. | В |
| F-SET-4 | Через UI настраиваются: адрес и имя отправителя, кодировка; SMTP (включение, сервер, порт, SSL, пользователь, пароль); группы для рассылки; число потоков; задержка между письмами; повторная отправка (включение, задержка, максимум попыток); каталог и срок хранения задач; удаление устаревших и пересоздание задач. | В |
| F-SET-5 | Перед сохранением настройки проверяются: потоков ≥ 1; максимум попыток ≥ 1 при включённых повторах; корректность адреса отправителя и получателей; существование кодировок; допустимость имён групп (не пустые, без `;` и символов, недопустимых в имени файла); наличие файла текста у группы. | В |
| F-SET-5a | Незаполненные параметры, нужные только для отправки (SMTP-сервер, адрес отправителя), не мешают сохранению: например, группы можно настроить до SMTP. Отклонённое сохранение пишется в журнал. | В |
| F-SET-6 | Пароль SMTP не передаётся в браузер. Пустой пароль при сохранении означает «не изменять». | В |
| F-SET-7 | Сохранение файла атомарно (запись во временный файл и замена). | С |
| F-SET-8 | Изменённые настройки применяются со следующего прогона без перезапуска сервиса. | В |
| F-SET-9 | Списки получателей очищаются от пробелов и дубликатов при сохранении. | С |

#### 3.2.2 Группы и тексты писем

| ID | Требование | Приоритет |
|---|---|---|
| F-GRP-1 | Оператор может добавлять, переименовывать и удалять группы. | В |
| F-GRP-2 | Для группы задаются: тема, путь к файлу текста, кодировка, актуальность, получатели (по одному в строке). | В |
| F-GRP-3 | Текст письма группы редактируется в UI и сохраняется в файл группы в её кодировке (или общей; по умолчанию UTF-8) без BOM. | В |
| F-GRP-4 | Чтение и запись текста возможны только для групп, сохранённых в настройках. | В |

#### 3.2.3 Выполнение рассылки

| ID | Требование | Приоритет |
|---|---|---|
| F-RUN-1 | Рассылка запускается только по команде оператора (кнопка «Запустить рассылку»). Автоматического запуска нет. | В |
| F-RUN-1a | Перед запуском проверяется готовность настроек: корректность значений; при включённом SMTP заданы сервер и адрес отправителя; есть хотя бы одна группа; группы из «Группы для рассылки» существуют; у каждой выбранной группы есть непустой файл текста и получатели. Иначе запуск отклоняется с перечнем причин (HTTP 400) и записью в журнал. | В |
| F-RUN-2 | Одновременно выполняется не более одного прогона; повторный запрос во время прогона отклоняется. | В |
| F-RUN-3 | Прогон обрабатывает группы из параметра «Группы для рассылки» (через `;`), а если он пуст — все группы. | В |
| F-RUN-4 | Для каждой группы создаётся задача, идентифицируемая именем группы и MD5 текста письма. Существующая задача переиспользуется (если не включено пересоздание задач), поэтому уже отправленные письма повторно не отправляются. | В |
| F-RUN-5 | Прогон продолжается, пока каждый элемент каждой задачи не будет отправлен или не станет «мёртвым»: исчерпаны попытки либо истекла актуальность. | В |
| F-RUN-6 | При ошибке отправки элемент получает время следующей попытки = время ошибки + задержка повторной отправки. Между проходами сервис ожидает ближайшего времени повторной попытки (не менее 1 с). | В |
| F-RUN-7 | При выключенной повторной отправке каждому получателю даётся ровно одна попытка. | В |
| F-RUN-8 | Отправка выполняется в заданном числе потоков с задержкой между письмами в пределах потока. | С |
| F-RUN-9 | Состояние задачи сохраняется в файл после каждого прохода, в том числе при остановке прогона. | В |
| F-RUN-10 | Задача, обработка которой завершилась исключением (например, повреждённый файл), исключается из прогона с записью ошибки в журнал. | В |
| F-RUN-11 | При выключенном SMTP отправка имитируется: элементы помечаются обработанными без отправки. | С |
| F-RUN-12 | Устаревшие файлы задач (старше срока хранения) удаляются, если это включено. | С |
| F-RUN-13 | По команде «Остановить» прогон прерывается; результат прогона — «остановлена». | В |
| F-RUN-14 | По завершении фиксируются время начала и окончания, результат («завершена», «ошибка», «остановлена») и текст ошибки. | В |

#### 3.2.4 Мониторинг

| ID | Требование | Приоритет |
|---|---|---|
| F-MON-1 | UI показывает список задач: имя, даты создания и изменения, всего, отправлено, ожидают, с ошибкой, не отправлено. | В |
| F-MON-2 | UI показывает элементы задачи: получатель, состояние, время последней попытки, остаток попыток, текст ошибки. | С |
| F-MON-3 | Файлы задач доступны для чтения во время прогона. | В |
| F-MON-4 | Оператор может удалить задачу вне прогона, чтобы следующий прогон отправил тот же текст заново. | С |

| ID | Требование | Приоритет |
|---|---|---|

| ID | Требование | Приоритет |

| ID | Требование |
|---|---|
| D-1 | Файл настроек — JSON; комментарии и завершающие запятые при чтении допускаются; интервалы времени — в формате `[д.]чч:мм:сс`. |

### 3.6 Атрибуты качества

| ID | Атрибут | Требование |
|---|---|---|
| Q-1 | Надёжность | Ошибка в одной группе или задаче не прерывает обработку остальных. |
| Q-2 | Надёжность | Повреждённый файл настроек не мешает запуску сервиса и UI. |
| Q-3 | Надёжность | Остановка прогона или сервиса не приводит к повторной отправке уже отправленных писем (см. F-RUN-9). |
| Q-4 | Безопасность | По умолчанию сервис слушает только `localhost`; открытие в сеть — осознанное действие администратора. |
| Q-5 | Безопасность | API задач принимает только имена файлов `*.task` без путей (защита от выхода за каталог задач). |
| Q-6 | Безопасность | Пароль SMTP не возвращается API. |
| Q-7 | Сопровождаемость | Логика рассылки изолирована в `Sending/` и не зависит от ASP.NET Core. |
| Q-8 | Переносимость | Сервис собирается и работает на Windows и Linux без изменения кода (кроссплатформенность). |
| Q-9 | Надёжность | При штатной остановке (Ctrl+C, SIGTERM, остановка службы) прогон прерывается с сохранением состояния задач. |

## 4. Проверка требований

Автоматические тесты — проект `EmsService.Tests` (кейсы описаны в `EmsService.Tests/TEST-CASES.md`):
S — сервис рассылки (F-RUN-*), H — хранилище настроек (F-SET-*), W — фоновый сервис (F-RUN-1, F-RUN-2,
F-RUN-13, F-RUN-14).

| Требования | Метод | Критерий |
|---|---|---|
| UI-1…UI-8 | Демонстрация | Вкладки и кнопки работают в браузере, ошибки консоли отсутствуют. |
| API-1…API-11 | Тест (HTTP) | Коды ответов и формат соответствуют таблице 3.1.2. |
| F-SET-1…F-SET-9 | Тест | Некорректные настройки отклоняются с перечнем ошибок; корректные сохраняются в файл; пароль не возвращается. |
| F-RUN-1, F-RUN-2 | Тест | Повторный `POST /api/run` во время прогона возвращает 409. |
| F-RUN-5…F-RUN-7 | Тест | При недоступном SMTP и 3 попытках прогон завершается, когда у всех элементов `AttemptsLeft = 0`. |
| F-RUN-9, F-RUN-13 | Тест | После остановки прогона файл задачи содержит результаты выполненных попыток; результат — `Stopped`. |
| F-RUN-11 | Тест | При выключенном SMTP прогон завершается, все элементы учтены как отправленные. |
| F-LOG-1…F-LOG-4 | Инспекция | Записи присутствуют в файле, консоли и на вкладке «Журнал». |
